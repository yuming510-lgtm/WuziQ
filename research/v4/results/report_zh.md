# V4 ABC 搜索算力扩展实验报告

- 实验：`abc_search_compute_v4_2026-10-19`；9×9 棋盘；固定局面：12 个。
- 实际记录：252/252 条，唯一 run ID；共同完整深度评分比较 183 次，差异 0 次。
- 本轮测量搜索效率和固定局面的战术选择，不包含 AI 对战胜率，也不进行模型训练。
- 当前运行环境未暴露本会话的 Codex 基础模型与推理强度字段，无法独立核实“Luna / Max”配置；算法和实验数据均来自本地仓库代码实际运行。
- A 使用原规则选择器，仅测量实际决策时间；没有人为等待。B 为纯 Minimax，C 为相同 Minimax 加 Alpha-Beta。
- B/C 按相同候选集、排序和评价函数迭代加深；每条记录的最大深度等于局面剩余空格数。超时层不会覆盖上一个完整层结果。

## 搜索深度与算力趋势

C 在 10 秒及以上预算中有 28/36 个实测 run 完成超过 4 层的迭代深度上限。该数值仅覆盖固定局面，不能外推为对弈胜率。
预算从 50ms 增加到 50s 后，需同时查看完成深度和有效节点；若搜索在更高预算仍常超时，说明候选树增长很快。若深度或节点增长放缓，应结合局面分支数理解，不能仅凭预算标签推断搜索已穷尽。
B 的平均已完成迭代深度上限从 50ms 的 1.08 增加到 50s 的 3.08；C 从 1.92 增加到 9.58。C 在 10s、20s、50s 下分别有 7/12、9/12、12/12 个局面超过 4 层。
C 的 50s 平均已完成迭代深度上限为 9.58，比 20s 的 9.08 高 0.50；平均节点数则从 144962 增至 307733。这是固定局面集合上的收益递减信号，不能视为整体棋力饱和的证明。
C 的单节点吞吐量约为 6713 节点/秒，低于 B 的 13310 节点/秒；Alpha-Beta 的收益来自更少节点达到相同完整深度，而不是每个节点执行得更快。

## 实际运行时间与截止偏差

修正版本正式矩阵实测 1903.905 秒；修正版本预检实测 777.148 秒；两者合计 2681.054 秒（44.68 分钟）。
首轮因截止边界问题而废弃的预检和矩阵共耗时 2682.754 秒；这些数据未计入本报告统计。含复核重跑在内，所有预检与矩阵实测合计 5363.808 秒（89.40 分钟）。
最终记录中有 2 条实测 wall-clock 略超名义预算，最大超出 5.432 毫秒；均保留原始耗时并计入超时统计。迭代只有在截止前完整结束才更新根结果，操作系统调度和返回路径可能造成少量 wall-clock 偏差。
最终有效矩阵相对预检的墙钟误差为 5.03 秒（0.26%）。

## 结论边界

B/C 根评分一致性只验证相同完整搜索深度下的实现正确性；Alpha-Beta 的主要收益是减少达到同一深度的搜索工作量。更深搜索会改变启发式有限深度选择，但本实验没有随机抽样对手赛或统计棋力设计，不把这些搜索指标写成胜率或稳定强弱结论。
