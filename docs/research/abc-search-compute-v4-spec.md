# V4 ABC 搜索算力扩展实验规格

## 研究问题

测量规则 AI A 的实际决策耗时，以及纯 Minimax B 和 Minimax + Alpha-Beta C 在 9×9 棋盘、七档墙钟预算下的搜索深度、节点成本和评分稳定性。A 是规则基线；本轮不进行 AI 对战，也不涉及神经网络或训练。

## 算法约束

- A 继续调用 V3 已有规则选择器，不睡眠、不填满预算。
- B/C 使用相同的候选落点、稳定排序、评价函数和递归逻辑；C 只启用 Alpha-Beta 界限更新与剪枝。
- B/C 使用 deadline-aware 迭代加深。每轮完整后才替换当前可返回结果；超时的未完整层只记入总搜索成本，不用于最佳着法或已完成深度。
- 实验深度上限取当前棋盘剩余空格数，原有交互默认值不变。每个完整迭代记录根评分、着法、节点、剪枝和耗时。
- 所有同一局面的预算共享棋盘、当前玩家和确定性种子。每一组同局面、同预算 B/C 完整共同深度必须有相同的根最优评分；并列着法可以不同。

## 固定实验矩阵

- 棋盘：9×9。
- 棋盘状态：至少 12 个随仓库提交的合法、非终局、固定着法序列，覆盖开局、中局、残局、直接进攻和强制防守。
- 模型：A、B、C。
- 每步预算标签：0.05、0.2、1、5、10、20、50 秒。A 每个预算标签仍只测一次自然决策耗时。
- 规模：12 × 3 × 7 = 252 个唯一 run ID；所有局面和预算逐项落盘并 `fsync`。
- B/C 搜索深度上限按各状态剩余空格数设置，避免把配置上限误报为实际完成深度。

## 数据与指标

每条原始 JSONL 记录含稳定 `run_id`、实验与代码版本、局面 ID/类别/着法、玩家、模型、预算、种子、最佳落点、根评分、完整逐层轨迹、完成深度、总节点、剪枝次数、根候选数、实际耗时、节点/秒、超时与起止时间。逐层轨迹单独保留完整层计数，便于和可能不完整的最后一层区分。

汇总报告绘制 B/C 完成深度、总节点、节点/秒、剪枝比例及每个预算下的表现；A 单独展示实际耗时分布。对共同完整深度逐行比对 B/C 根评分，并报告评分不一致为零的验证结果。剪枝比例定义为 `C 截止节点 / C 总节点`，仅作搜索工作量指标，不解释为棋力增益。

## 持久化与可复现性

- 配置中固定局面、预算、种子派生规则和当前基线 commit；`run_id = position_id/model/budget_ms`。
- 运行器启动时校验已有记录、拒绝重复 ID、跳过已完成 ID；每条记录追加后 flush + `fsync`，进度文件原子替换。
- Drive 恢复包只包含实验配置、代码版本、进度、完整原始 run JSONL 和 SHA-256 清单。上传后必须下载/读取、验证校验和并实际恢复到临时目录；确认新文件有效后才可删除旧正式快照。
- 研究分支从 V3 commit 创建，所有产物留在 V4 路径，绝不改写 main 或 V1–V3 内容。

## 分析边界

本轮是搜索性能与战术正确性测试，不是对弈胜率实验。预算增加显示搜索更深或同层工作量更多，不等同于实际棋力必然提升。尤其不能仅凭 12 个固定局面声称强度排名。
