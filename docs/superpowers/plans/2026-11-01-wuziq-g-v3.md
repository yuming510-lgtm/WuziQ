# WuziQ G V3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compare G0 random initialization with F2-initialized G-F2 under matched PUCT-64 self-play, seed, state, and CPU budgets, after diagnosing BatchNorm handling.

**Architecture:** Preserve V2 PUCT/board/replay/evaluation primitives and extend the G trainer with an explicit backward-compatible BN mode. Add V3-specific deterministic schedules, probe/runner/evaluation/report/snapshot control; no V1/V2 results or checkpoint is rewritten.

**Tech Stack:** Python 3.12, PyTorch 2.15 CPU, NumPy, Matplotlib, pytest, Git, Google Drive connector.

**Spec:** `docs/superpowers/specs/2026-11-01-wuziq-g-v3-design.md`

## Global Constraints

- Board rules: 9×9 free Gomoku; model: 32 channels and 2 residual blocks; PUCT: exactly 64 simulations per move.
- Only initial weights differ between G0 and G-F2; G0 gets independent deterministic weights per seed and G-F2 always loads frozen F2 SHA `50164ad9b139e0c47c1b1af7497f670c26e9864a81c10c02de0ff4426b2d0257`.
- Each route must finish at least 10,000 budgeted states per registered seed; target extension 30,000 and only extend equally by paired seed, under a registered CPU cap including evaluation.
- Train targets use self-play PUCT root visits and final game outcome only; never train from C/E5, F rows, tactical rewards, or hard-coded tactics.
- Training openings are 50% empty board and 50% legal random 4-ply, deterministic and paired across routes. Dev/blind use only random 4-ply openings and are D4-disjoint from training random openings, one another and prior V1/V2 nonempty openings; the universal empty-board root is not claimed as held out.
- Each registered seed has an independent random G0 initialization; target 2 paired seeds and fall back to 1/route only if a measured cap cannot fit both 10k baselines. With 1 or 2 seeds, route-level generalization remains exploratory and seed results stay separate.
- Final blind tests every seed checkpoint using at least 20 unseen opening groups per matchup and both colors; development cannot use blind outcomes.
- Every checkpoint is measured on a fixed, rule-validated tactical set covering immediate win, unique block, edge, and false-threat positions; it is evaluation-only and adds no move rule/reward/training label.
- Promotion requires 12 development opening pairs, PUCT score ≥0.625, paired-opening bootstrap lower 95% bound >0.5, and black/white score each ≥0.5; weaker G0 does not reduce its registered training quota.
- Backup schedule uses cumulative effective runtime thresholds 1, 3, 7, 13, 23, 39, 65 hours, then every 26 hours; a new V3 snapshot must download, SHA-256 verify, and restore into an empty directory before the previous V3 snapshot is removed.
- Branch is `research/alphazero-g-v3` based on `c95eb5aa919c769af11ea6b7fc22df2594ae1c28`; V1/V2 files, branches, and checkpoints remain unchanged.
- Historical branch-guard test files are excluded from V3 applicable suite: V6.2/V6.3 four files and `tests/test_alphazero_g_v2_snapshot.py`.

## Review Focus

- A training game may finish beyond the budget prefix; preserve complete terminal labels while excluding tail states from training, count tail simulation cost, and test both exact quota and replay prefix.
- G0 and G-F2 must not share mutable models, optimizers, replay, or RNG state; test different G0 seeds have different initial hashes while matched F2 starts are identical.
- BN restore must change only running buffers, not affine parameters or trained convolution/head weights; test exact restoration and subsequent deterministic evaluation.
- Random-opening train/dev/blind schedules may collide after rotation/reflection; test D4 canonical disjointness, repeatable empty-root category, 50/50 training mix, and fixed schedule hash.
- Resume can encounter a partially written last JSONL record or completed game without a matching state checkpoint; test truncation/repair and reject conflicting or unregistered progress.
