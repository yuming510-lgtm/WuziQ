# WuziQ G V6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Continue the frozen V5 standard AlphaZero 9×9/400-simulation run to 20,000 real self-play states and measure whether strength improves under identical evaluation search budgets.

**Architecture:** Reuse V5's vendored AlphaZero policy/value network, PUCT, self-play, optimizer, data augmentation, replay buffer, and exact training configuration. Add V6-only experiment registration, resumable namespaced artifacts, stage evaluation, snapshot, audit, and report code; do not write into V5 data paths. Resume from the V5 `reference400_empty` complete training state only after verifying optimizer, replay, all RNGs, and model weights.

**Tech Stack:** Python 3.12, PyTorch CPU, NumPy, pytest, JSON/JSONL/NPZ, Matplotlib, GitHub, Google Drive.

**Spec:** User request in this conversation; baseline implementation and results in `research/g_v5/REPORT.md`.

## Global Constraints

- Board is 9×9 freestyle Gomoku; five in a row wins.
- Use V5's original AlphaZero reference implementation and training settings; 400 configured PUCT playouts per self-play move.
- Target 20,000 cumulative unaugmented self-play states, continuing from V5's 1,514-state checkpoint; record the actual overshoot at whole-game boundaries.
- Preserve V5's replay buffer, optimizer, model, Python/NumPy/PyTorch RNG states, training data, checkpoints, and results unchanged.
- No teacher model/data, human labels, handcrafted reward, inference-time tactical patch, or changed reward/objective.
- Primary comparisons use paired color-swapped openings and fixed PUCT-64; also report PUCT-400 separately.
- Final A/B blind evaluation uses new pre-registered openings and at least 40 games per opponent at each search budget; development data alone selects the checkpoint.
- CPU hard cap is 10 CPU hours. Stop only at a durable game/pair boundary if the cap is reached, preserve progress, and report exact remaining work.
- Every checkpoint, game, stage, and recovery snapshot is uniquely identified, atomically written, and replay/audit verified.

## Review Focus

1. Resume must restore the exact V5 model, Adam slots, 10,000-row replay buffer, and all RNG state; test exact state equality before training.
2. The cumulative state count must not be confused with games, augmented samples, or additional states; test counts at every milestone.
3. PUCT-64 and PUCT-400 must evaluate the same checkpoint and opening groups; test pairing and budget metadata.
4. Blind openings must be distinct from V5 and all V6 development openings; test seed, D4-canonical uniqueness, legality, and nonterminal status.
5. Interrupted games/pairs must not be counted twice; test stable IDs, atomic writes, and idempotent resume.
