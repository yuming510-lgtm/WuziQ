# WuziQ V6 implementation plan

## Goal

Implement E1–E5, validate tactical proof semantics and state safety, run a resumable paired V6 ladder with exact V5.1 reuse, then publish the measured results and implementation.

## Architecture

New code lives under `src/research/v6/`; new tests live under `tests/`; configs and results live under `configs/v6/` and `research/v6/`. Existing A/B/C/D implementation files remain unchanged. A small V6 tournament adapter calls A/B/C/D through their current public selector and E1–E5 through one V6 engine registry.

## Tech Stack

Python 3.12, pytest, existing `GomokuBoard`, standard library for search, JSONL/CSV/SVG outputs, SHA-256 for frozen inputs and recovery files.

## Spec

Binding design: `docs/superpowers/specs/2026-10-22-wuziq-v6-design.md`.

## Global Constraints

- All claims must be supported by tests, complete game records, or replayable proof certificates.
- No tests are added after implementation without first observing their failure.
- Preserve V5.1 source data and every A/B/C/D engine file.
- Search timeout returns a legal fallback and never upgrades partial work to a proof.
- A/B/C/D versions and E families are distinct model identities; reuse is exact-match only.
- Any inference is metadata, not an empirical game or win.

## Review Focus

See the binding spec's Review focus section. In particular audit full defender coverage in proof verification, timeout mutation recovery, TT/PVS correctness, exact source reuse, route-local stopping, and score reconciliation.

## Tasks

### Task 1: Baseline, fixtures, and V6 immutable inputs

- Capture V5.1 baseline evidence and exact reusable paired-game manifest.
- Add deterministic tactical position fixtures and failing tests for the V6 public registry, fallback legality, deadline behavior, state restoration, and proof certificate validation.
- Freeze V6 config: family list, budget ladder, V5.1 opening catalog, deterministic paired color seeds, engine pins, and expected full schedule size.
- Add a V6 progress ledger and initial recovery payload shape.

**Expected:** baseline suite is green; new API tests fail for missing V6 code; fixture histories are legal/nonterminal; V5.1 candidate reuse groups replay as exactly 73 complete groups with one partial excluded.

### Task 2: Sound tactical search E1–E4

- Implement common deadline, legal fallback, tactical move generation, reversible board guards, and proof certificate verifier.
- Implement VCF, VCT, threat dependency/conflict ordering, and proof-number search.
- Add positive/negative tactical tests, complete-defense coverage tests, timeout tests, deterministic tests, and board-state restoration tests.

**Expected:** positive fixtures produce replay-valid proofs; false-proof/counter-win fixtures do not; every returned move is legal; board/history are byte-identical after search; timeout yields `unknown` plus legal fallback.

### Task 3: E5 PVS/TT and component ablation

- Implement a separate iterative-deepening PVS search, deterministic Zobrist hash, depth-qualified TT bounds, move ordering, and bounded tactical extensions.
- Add root-value/perft-like equivalence checks against existing C at fixed shallow depth, TT collision/side-to-move tests, time-limit tests, and independent ablation runs.

**Expected:** complete-depth root values agree with C when both use the same full candidate set and evaluation; all E5 selected moves replay legally; ablation runner produces baseline plus each single-component toggle on the same positions.

### Task 4: V6 schedule, reuse, resumable runner, and Drive snapshot validation

- Materialize all independent routes and the theoretical maximum schedule; validate unique pairs/game IDs, route DAG, paired colors, and opening assignment.
- Import only exact replay-valid paired V5.1 groups; retain unmatched/unpaired/inferred source items as excluded audit records.
- Implement append/fsync, resume/unique-ID checks, per-group progress, route-local stop/inference, game replay, and V6-only snapshot upload/download/hash/restore/rotation.
- Validate Drive through the already-completed probe and then write a real initial V6 snapshot.

**Expected:** 456 routes / 1,428 unique groups / 2,856 potential games; no same-family groups or duplicate pairings; exactly 73 V5.1 groups eligible, 146 games reused, one partial observation excluded; interrupted fixture resumes without duplicate score.

### Task 5: Tactical acceptance and tournament preflight

- Run the complete existing test suite and all tactical suite gates.
- Benchmark each E engine on representative opening, attack, defense, and midgame positions at all seven budgets, including E4 PNS node/memory behavior and E5 completed depth.
- Record CPU/RAM/disk, decision-time distributions, per-game pilot lengths, and optimistic/central/conservative total cost estimates.
- Freeze the official schedule and start time before new official games.

**Expected:** correctness gates pass before any formal game; preflight clearly separates reused games, excluded data, projected new games, and estimated runtime/resource needs.

### Task 6: Run all active routes and generate research artifacts

- Execute active paired groups in deterministic schedule order, persisting every completed game and updating progress after each group.
- Rotate only the V6 Drive recovery snapshot after upload, download, hash, and empty-directory restore succeed; continue after verified recovery if needed.
- Generate Chinese report, CSV/JSON summaries, version/family win matrices, color heatmaps, compute curves, E5 ablations, proof diagnostics, and SVG figures.

**Expected:** all route states are tested, inferred, or unrun with an explicit reason; every official game replays legally; result counts and score formulas reconcile.

### Task 7: Full verification and GitHub delivery

- Run all tests; validate source reuse provenance, tactical certificate validity, schedule/routes, every game, all stats, report/figure input hashes, and clean worktree state.
- Commit V6 source/config/results/report and push only `research/advanced-search-v6`; verify remote branch head equals the local commit.

**Expected:** full suite passes, all artifacts are committed, `git ls-remote` shows the exact pushed SHA, and V1–V5.1 plus `main` remain unchanged.
