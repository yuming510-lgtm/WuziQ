# WuziQ G V1 — AlphaZero-Lite 自我对弈强化学习设计

## 意图

在 F V2 提交 `89fecf2a12c58cc27c985f588d5023ad9d198c80` 上新增独立的 G V1 分支，验证 9×9 五子棋中“策略价值网络 + PUCT-MCTS + 自我对弈”能否带来可测量的策略和棋力提升，并比较随机初始化 G0 与 F2 初始化 G-F2 的学习效率。F1、F2、A–E 的代码、模型、配置和历史成绩均作为冻结对照。

## 目标与非目标

- 实现 AlphaZero 式 PUCT；树搜索使用网络策略先验与网络叶节点评估，依据 MCTS 根访问次数形成策略目标，依据完整对局胜负形成价值目标。
- G0 与 G-F2 使用相同的网络结构、模拟次数、训练环境步数、更新次数、开局赛程和 CPU 线程数。两组拥有分离的模型、经验池、种子和恢复状态。
- 自我对弈之外不得使用 F1/F2 监督数据、C/E5 教师标签、人工战术奖励或必胜/必防推理规则。A、B、F1、F2 仅作为冻结评测对手。
- 比较训练前后纯网络与固定模拟预算 PUCT 的实战结果；训练成绩不能把增加搜索量算作网络学习收益。
- 仅做 9×9 AlphaZero-Lite；不开发 15×15，不改 A–F，不展开传统搜索算法研究，不启动任何外部数据或其他强化学习方案。

## 设计取舍

1. **独立 G 实验包（采用）**：在 `src/research/alphazero_g/` 内实现 PUCT、自我对弈、回放和训练；复用 `PolicyValueNet`、`GomokuBoard` 与 F2 checkpoint 格式。这样训练经验源可被硬性限制为 G 自我对弈，且不会触碰冻结历史代码。
2. **扩展 F V2 trainer（不采用）**：虽能复用检查点和损失代码，但现有 trainer 面向带监督标签的样本，容易意外混入 F 训练行，且不适合存储 MCTS 访问分布、整局终局标签和双臂独立回放。
3. **给既有 D-UCT 加网络评分（不采用）**：D 使用旧 UCT/rollout；仅替换启发式会混淆算法定义。G 必须独立实现以策略先验、价值网络和交替视角回传为基础的 PUCT。

采用 PyTorch 的既有 CPU/GPU 自动设备选择；当前实测资源是 3 个 CPU 核、约 8.9 GiB 可用内存、无 CUDA、工作区磁盘约 28 GiB 可用。生产训练预算只在 PUCT、完整自我对弈与训练吞吐预检后按实测冻结，正式开跑后不按盲测结果改预算。

## 核心接口

- `src/research/alphazero_g/puct.py`：`PUCTConfig`、`PUCTNode`、`PUCTResult`、`PUCTSearch.search(board, to_move, simulations, *, add_root_noise, temperature, seed)`。节点保存 prior、visit count、value sum、合法子节点；Q 以节点当前行棋者为视角，沿路径每层翻转符号。训练时仅根节点混入 Dirichlet 噪声；评测时关闭噪声并确定性选点。
- `src/research/alphazero_g/selfplay.py`：运行一局完整自我对弈，将每个状态、归一化根访问分布、行棋方和终局值写入经验池。终局值为当前状态行棋方视角的 `+1/-1/0`。每局后追加并原子更新唯一游戏 ID 与进度。
- `src/research/alphazero_g/replay.py`：仅接受 schema 标记为 `self_play` 的 G 轨迹，按固定容量保留近期整局经验；批次按游戏均匀抽样，避免长局主导回放。状态与策略同步做 D4 变换；不加载 F1/F2 数据行。
- `src/research/alphazero_g/training.py`：策略损失为对访问概率的交叉熵，价值损失为最终结果 MSE；AdamW、固定 batch/updates、可恢复优化器、学习率、RNG、回放索引和进度。G0 用注册随机种子初始化，G-F2 从校验过 SHA-256 的 F2 权重 warm-start。保存初始、阶段与完整 resume checkpoint。
- `src/research/alphazero_g/experiment.py`：确定性、合法且互不重叠的 self-play/development/blind 开局表；注册预算与阶段索引；逐局结果汇总、paired 统计与纯网络/PUCT评测。
- `scripts/preflight_g_v1.py`、`scripts/run_g_v1.py`、`scripts/evaluate_g_v1.py`、`scripts/report_g_v1.py` 与 snapshot/restore 脚本负责性能测量、实验驱动、报告及恢复。

## 搜索与学习语义

输入沿用 F2 的三平面编码：当前方棋子、对方棋子、空位；输出为 81 个策略 logits 与当前方视角标量价值。PUCT 每次只对非终局新叶调用网络。父节点选择子节点时以父方视角最大化 `-Q(child) + c_puct * prior * sqrt(parent_visits)/(1+child_visits)`。终局子节点值按其 `to_move` 视角赋值；反向传播每跨一手取负。终局节点不再调用网络；满盘平局价值为零。所有行动集合只含空位。

自我对弈在早期手数使用正温度从访问分布采样，后期降温；训练时加根 Dirichlet 噪声，开发及盲测固定 argmax/固定搜索策略。经验池只使用本模型自身完整对局，按多阶段历史回放；不添加规则特征、人工奖励、教师动作或战术覆盖。评测同时记录网络原始熵与 MCTS 访问熵、搜索节点/模拟次数、环境步数、CPU耗时和终局分布。

## 预算和评测协议

先用 16/32/64 模拟比较至少 3 个代表性开局/中局局面的单步延迟，并分别完整运行 G0 与 G-F2 自我对弈预检；使用实际自我对弈局速、MCTS前向次数和 CNN batch 更新吞吐量估算乐观/中性/保守成本。正式预算注册在 `research/g_v1/config/experiment.json`，明确每臂模拟数、环境步数、更新数、replay 容量、阶段 checkpoint 与评测节点；两个训练臂严格匹配。

评测对手冻结为 A（自然规则 AI）、B（V5.1/V4 代码路径的纯 Minimax，50ms）以及 F1、F2 纯策略网络。V1 不追加 C，原因是主要假设是 F2 warm-start 相对从零的收益，C 会增加 CPU 与对手预算异质性而不回答必要问题。G 的纯策略网络和 PUCT 使用同一 checkpoint 与固定搜索模拟预算，在完全相同配对开局、黑白换色下分别评测。开发赛用于阶段 checkpoint 选择；最终盲测开局独立、预先冻结，只用于选定模型的最终评测，不回流训练或改配置。最终对局数量和每个检查点安排以预检后预注册配置为准。

**步数计量裁定**：完整对局长度由棋局决定，不可能同时强制每个对局恰在同一 plies 结束并保留真实终局标签。每臂训练数据预算定义为精确相同的 `budgeted_environment_steps`：完整结束最后一局以得到真实胜负，但只将达到预算上限前的状态计入各臂经验池和训练步数；超过上限的最后一局尾部仅用于确定前缀状态的真实终局回报，额外 plies 和模拟数作为 `completion_overrun` 独立记录，不作为训练样本。预算设得远大于 81 步以使尾部占比很低。这样保持有效训练交互步数、更新数和每步模拟数相等，同时如实披露真实执行 plies 与 CPU 成本的少量尾差。

## 恢复与交付

每局轨迹与训练状态采用原子落盘，游戏 ID 唯一；恢复时验证分支提交、代码/配置哈希、checkpoint/replay 哈希并去重。Drive G V1 独立目录按 1、2、4、6、10、16、26 小时渐进间隔保留最新单份恢复包；新包必须回下载、SHA-256 一致并在空目录恢复成功后才删除上一份。快照只包含 G 恢复所需代码引用、配置、当前 checkpoint/优化器/RNG、经验池、进度和已完成对局，不写入无关日志。

最终报告给出两臂实际环境步数、更新量、网络/PUCT每步 CPU 时间与学习曲线、各冻结对手的胜平负与颜色分项、训练与搜索增益拆分、置信区间、小样本/算力限制、恢复及复现信息。所有胜负和成本来自保存的真实对局/训练计时；没有模型训练以外的假数据或把 MCTS 计算收益算作网络学习收益。
