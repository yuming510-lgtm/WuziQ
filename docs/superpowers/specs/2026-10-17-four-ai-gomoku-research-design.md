# 四种五子棋 AI 算法开发与对弈评估设计

## 目标与边界

在现有 WuziQ 规则、棋盘、Web 与 CLI 基础上，保留 A 启发式基准，并增加纯 Minimax（B）、Minimax + Alpha-Beta（C）和传统 UCT MCTS（D）。算法不训练模型；研究产物是代码、可复现实验配置、逐局/逐手原始数据和中文分析报告。

正式实验包含 9×9 六组完整循环赛，每组 200 局、双方各执黑 100 局，总计 1,200 局；15×15 每组 20 局作为补充，共 120 局。赛事采用可复现的成对开局、颜色交换和唯一对局 ID。B/C 的决策能力用同局面、同候选、同评价函数、同深度的完整搜索单独验证；竞赛再用同一单步墙钟时限比较实战效率和棋力。

## 现状约束

- `GomokuBoard` 已定义落子、撤销、胜负检测和序列化；AI 不复制或改变规则。
- 当前 `select_ai_move` 是 A，遍历全部空点并使用全局随机数；保留该策略，增加可注入 RNG 以支持种子复现。
- Web 端只有 AI 执棋颜色选项；后端单例状态通过 Flask 路由更新。
- 核心和 CLI 使用 Python 标准库，Flask 是 Web 唯一运行依赖。

## 架构

### 搜索引擎

新增 `src/ai.py`，提供统一 `choose_move(board, player, model, config, seed) -> SearchResult` 接口。`SearchConfig` 固定共同候选半径、最大深度、单步时间上限、UCT 探索常数和随机种子策略；`SearchResult` 返回合法着法、耗时、节点数、完成深度、剪枝数、模拟次数和超时标志。

候选点规则对 B/C 完全相同：空盘只给中心点；其他局面返回已有棋子切比雪夫距离 2 内的空点，按立即胜、阻止对手立即胜、局部威胁和中心距离排序。候选为空时回退到全部空点。静态评价按棋盘上无对手棋子的五连窗口计分，并始终从根节点玩家视角返回分数。B 与 C 用同一候选顺序、评价、最大深度和迭代加深；B 不执行剪枝，C 仅额外维护 alpha/beta 界并计数 cutoff。引擎为协作式截止预留 1ms，配置仍为统一 50ms 上限；实际时长逐手记录。深度专项运行不设墙钟截断，二者根最优值须相等，最优着法须属于同一最优集合。

A 保留原启发式。D 实现标准选择、扩展、模拟、回传，选择使用 UCT（探索常数可配置，默认 √2）；模拟使用可复现随机数，并优先处理一步胜着和必挡点。模拟最多进行 24 手；达到上限时用共享静态评价映射为 [0,1] 回报，提前获胜/满盘则使用精确终局回报。这样 50ms 预算内不会因 15×15 的完整随机终局模拟而零次回传。无神经网络、权重文件或训练阶段。每步通过迭代加深/模拟上限与统一墙钟时限保护；超时返回最近完成的合法结果或首个合法候选，并记录超时。非法着法在正式竞赛中记为该模型负局，不能静默修正。

### 交互与竞赛

Web 配置保留 `ai_side`，增加独立 `ai_model` 选择，默认 A；人机对弈继续由现有 `/move` 流程驱动。AI 自动对弈由可选模型对的研究 runner 执行，避免把批量运行塞入交互请求。

`src/research/runner.py` 从固定种子生成每对算法的 paired opening，并按两种颜色交换执行。每局记录配置版本、ID、棋盘、黑白模型、开局、终局和每手模型/着法/时长/节点/深度/模拟/超时。一个 JSONL 行对应一局，完成后 flush + fsync；`progress.json` 原子替换。恢复以已完成 game ID 集合为准，遇到已完成 ID 永不重复计数；中断中的局按相同 ID 和随机种子重跑。

`src/research/efficiency.py` 使用固定种子局面集比较 B/C 根价值、最优着法集合、节点数、C 的剪枝比例与用时，并从正式比赛按有效深度汇总相同时间预算下的表现。`src/research/metrics.py` 计算六组胜负、纯胜率、平局计半的得分率、配对开局区间、平均思考时间和颜色优势；报告明确显示区间重叠时排名差异不确定。

检查点只含版本化配置、基种子、进度索引、已完成对局和校验和。每局本地原子落盘；预计任务超 24 小时则每约 24 小时将单一 ZIP 检查点上传 Drive，读回并校验之后才能删除旧版。恢复演练先从 Drive 下载小检查点，加载并确认完成 ID 被跳过。连接器令牌不写入仓库或快照。

## 固定实验配置

- 9×9：每个无序模型对 200 局、100 个 paired-opening 区块、每种颜色 100 局，共 1,200 局。
- 15×15：每个无序模型对 20 局、10 个 paired-opening 区块、每种颜色 10 局，共 120 局。
- 开局种子从配置中的固定整数通过稳定 SHA-256 派生；不使用 Python 内置 hash。
- 单步时限对四模型和两种棋盘统一，配置初值 0.05 秒；搜索深度上限 4。小基准后先估算总运行时，才启动正式赛。超时、非法落子、平局和胜负的记分规则固定并写入结果配置。
- 每组的纯胜率使用只看决胜局的 95% Wilson 区间；得分率按 paired opening 区块 bootstrap 95% 区间；全模型排名用六组总得分并附区间，不把不确定的小差值解释为能力差距。
- 效率实验不训练神经网络，也不报告训练、收敛或 checkpoint 指标。

## 持久化产物

- 配置：`configs/four_ai_experiment.json`
- 可恢复逐局数据：`research/results/9x9_games.jsonl`、`15x15_games.jsonl`、`progress.json`
- 派生汇总：`research/results/summary.json`、`efficiency.json`
- 中文报告：`research/REPORT.md`
- 可运行入口：`python -m src.research.runner`、`python -m src.research.efficiency`。

## 验收标准

1. A/B/C/D 均可通过统一接口单独运行并返回合法着法，A 原逻辑保持基准身份。
2. B/C 同深度同局面根值一致；Alpha-Beta 的节点数不高于 Minimax，至少一个可剪枝局面记录 cutoff。
3. UCT 四阶段、种子复现、超时回退和 MCTS 次数可观测。
4. Web 可选 AI 模型且 A 仍为默认；现有人机流程、CLI 和规则测试继续通过。
5. 检查点恢复演练证明重复 ID 被跳过，正式结果数据 ID 唯一且数量准确。
6. 每个算法对至少完成 9×9 200 局；B、C 分别参加全部三组，15×15 补充结果及完整中文报告真实引用原始数据。
7. 全部代码、测试、配置、数据、报告推送到独立研究分支。
