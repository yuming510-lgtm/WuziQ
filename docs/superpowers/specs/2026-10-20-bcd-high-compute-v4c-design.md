# V4C 高算力最终挑战赛设计

## 目标与范围

在 V4B 的独立分支 `research/abcd-final-v4b` 上建立 `research/bcd-high-compute-v4c`，只让 B、C、D 在 9×9 棋盘对局。V4C 新增 18 局，不导入或重复计数 V4/V4B 棋谱。A 不参加。

## 冻结赛制

- 对阵按规范顺序：B–C、B–D、C–D；每组 6 局。
- 每组三个 V4B 登记开局（731091、731092、731093）各下两局，黑白模型交换。
- B 使用 V4 已验证的纯 Minimax 迭代加深实现，单步上限 1 秒。
- C 使用同一评价函数、候选生成、候选排序及搜索逻辑，单步上限 200ms，仅启用 Alpha–Beta。
- D 使用 V4B 的 `MCTSAgent` 原版 D2/D3 配置、根节点/战术策略、跨步节点复用，仅将单步上限从 20 秒提高到 50 秒。
- 按稳定哈希从固定实验种子、对局 ID 和手数派生随机种子；不挑选开局或种子。
- 超时仍使用搜索引擎已返回的合法走法并记录超时；非法走法立即判负；未结束对局不写为正式结果。

## 实现设计

新增 V4C runner、统计/回放验证器、资源预检器、恢复归档器、CLI、配置、测试及 `research/v4c` 结果目录。逐局 JSONL 追加后 flush+fsync，再原子更新进度；游戏 ID 唯一且恢复时按 ID 去重。恢复包只保存配置、进度、完整棋谱和代码版本标识。恢复器必须检查包内 SHA-256、空目录提取及恢复后完成 ID 与进度一致。Drive 替换遵循先上传、再下载/哈希校验/空目录恢复，最后仅删除旧 V4C 快照。

## 验收

验证冻结配置和 18 局配对赛程、B/C 搜索参数一致性、D 的 50 秒预算、唯一 ID 与恢复逻辑、完整棋谱规则回放。正式 18 局全部完成后，输出逐局原始数据、汇总 CSV/JSON、趋势与战绩图、中文报告；将成果提交到独立分支，不改写基线分支。

## 推理与资源声明

实验只运行传统规则/搜索算法，不含神经网络或强化学习训练。资源估计以当前环境实测、V4B 的真实 D20 决策耗时和新的 D50 代表局面预检为依据。18 局为探索性小样本，D 的算力显著高于 B/C；区间仅作描述。
