# WuziQ G V2 实验设计

## 目标与边界

检验从冻结 F2 权重出发、只使用同一当前策略的 PUCT 自我对弈数据进行强化学习，是否能在固定搜索预算下获得可复现的棋力提升。实验沿用 9×9 自由五子棋、32 通道/2 残差块网络和 64 次 PUCT 模拟/落子。冻结 A、B、F1、F2、G V1 源码与结果；不引入教师标签、F 监督数据、人工奖励、搜索规则补丁或额外模拟次数。

## 实验组与学习率诊断

建立三个独立、配对的 G-F2 挑战者，全部从同一经 SHA-256 验证的 F2 checkpoint 初始化：

| 组 | 学习率 | 用途 |
| --- | ---: | --- |
| LR-1e-4 | 0.0001 | 主候选 |
| LR-3e-5 | 0.00003 | 低学习率候选 |
| LR-1e-3 | 0.001 | 退化诊断对照，预算与其他组相同 |

三组使用同一批预注册训练开局、相同随机种子规则、64 次模拟、经验池容量、批次大小、每状态更新比例及状态预算。每组有独立模型、优化器、经验池和 RNG 状态。训练候选彼此不共享 replay，保证标签只来自本组自身自我对弈。

## 计算预算与训练节点

首选目标是每组 20,000 个计费训练状态，累计 60,000 个状态，最多 2 CPU 小时。真实预检包括 16/32/64 次 PUCT 测速、完整 64-simulation 自我对弈局、各候选学习率的短更新、开发评估与存储峰值。用预检的保守时长估算完整任务。若保守估算超过 2 CPU 小时，预先等比例缩减三组状态预算并缩短评估赛程，同时保留 1k、2k、5k 及最终可达节点；不得先开始训练后依结果改预算。正式预算冻结到配置及其 SHA-256 后执行。

在 1,000、2,000、5,000、10,000、20,000（或预注册缩减上限）状态处保存候选。以小批次采集和频繁训练替代 V1 每 1,024 状态集中执行 64 次更新：目标更新频率为每 16 个预算状态一次 batch-16 更新。经验池按完整局及位置均匀采样，容量至少覆盖目标状态；记录经验池游戏数、位置数、采样分布和更新时间。

终局后超过状态配额的棋步是完整性所需的尾段，可保存在棋谱，但不计入训练状态、replay 或更新触发计数。所有预算样本仍使用完整终局胜负标签。

## 开局、分组与泄漏控制

用固定种子先生成互不重复的 4 手合法、非终局开局池。训练池不少于 128 组；开发池 8 组；最终盲测池 20 组。排除 V1 历史开局及彼此在旋转、翻转下等价的开局棋盘序列。生成器记录完整开局、开局 ID、生成种子及 schedule SHA-256。自我对弈按固定轮转顺序使用训练开局；颜色按预注册规则交换并记录。最终盲测池在模型/学习率选择完成后才开放给评估程序。

## 冠军—挑战者与开发选择

初代冠军为冻结 F2。每一检查点将每个候选在相同 8 个开发开局、黑白交换条件下，以纯网络与固定 PUCT-64 分别对 F2、A、B 评估；B 的截止预算固定为 50 ms/步。F2 是主冠军比较对象；A、B 是退化哨兵。规则与种子在查看候选成绩前写入配置。候选晋级条件为：

1. 在 PUCT-64 对当前冠军的 16 局开发配对中，得分率至少 0.625；
2. 按开局组配对 bootstrap 的 95% 区间下限大于 0.5；
3. 执黑与执白分项均不低于 0.5；
4. 相对冻结 F2，对 A、B 的 PUCT 得分率均未下降超过 0.125；
5. 棋谱和计时验证完整，无未处理的非法落子。

同一检查点多个挑战者都满足时，按 PUCT 对当前冠军得分率、再按配对区间下限、最后按较小学习率确定。候选若成为冠军，其后续检查点与其晋级时替换掉的冻结冠军比较，防止自我对局；其他候选始终挑战当时的当前冠军。开发集允许用于模型选择；最终盲测不得反过来选模型或调整参数。如果无人达标，F2 保持冠军，最佳候选仍作为研究产物报告但不宣称替代冠军。

## 诊断和指标

每阶段同时记录：累计局数、预算/实际状态及尾段、PUCT 模拟数、CPU/墙钟、optimizer 更新、损失、当前 LR、策略熵、价值 MSE、平均/分位棋长、胜负与颜色、经验池覆盖、每棋局采样量、每位置更新比。每阶段另测固定开发位置上的策略 KL/交叉熵/合法落点 argmax 一致率相对 F2 漂移，以及即时胜点/单点必防战术题正确率。这些只作评估诊断，不生成任何训练标签或推理补丁。

模型评估区分：

- 学习收益：同为 PUCT-64，最终 G 对冻结 F2 的配对胜率；并列出每个状态节点。
- 搜索收益：同一 checkpoint 下纯网络与 PUCT-64 分别评估。
- 冠军成长：仅当挑战者满足上述独立开发晋级规则才记为冠军更换。

## 正式盲测

最终使用 20 个未见开局组，每组按同一开局交换颜色，比较四个固定条件：冻结 F2 裸网络、冻结 F2+PUCT-64、最终选定 G 裸网络、最终选定 G+PUCT-64。四条件间每个两两组合各 40 局（240 局），每个条件分别对 A、B 各 40 局（320 局），总计 560 局。所有模型在同一颜色、开局和种子区组中配对，A/B 固定原始决策代码，B 预算为 50 ms/步。报告总得分率、胜平负、黑白分项、按开局组的配对 bootstrap 95% CI，以及同一开局下训练前后差值。F2+PUCT-64 对 G+PUCT-64 是同等搜索预算下的学习收益主比较；同一 checkpoint 的裸网络对 PUCT-64 是搜索收益。盲测只运行一次，不用于任何选择。

## 断点恢复、文件与快照

V2 采用独立目录 `research/g_v2`，不写入 V1。每个完成的完整棋局追加并 fsync 到 JSONL；训练状态通过临时文件、fsync 和原子替换保存模型、optimizer/scheduler、Python/NumPy/Torch RNG、候选 RNG、replay、进度、更新号和代码 SHA。game ID 由实验 SHA、LR 组、状态阶段和组内局号确定，加载时验证并去重。检查点仅在完整棋局/训练 batch 边界恢复。

快照间隔按累计有效计算时间 1、2、4、6、10、16、26 小时递进。V2 使用专用 Drive 目录，不触碰历史备份。新归档必须上传、下载回本地、SHA-256 一致、在空目录运行恢复校验并对清单/权重/JSONL 完整性成功后，才删除该 V2 目录内上一快照。正式开始前完成目录访问和一份小型快照往返演练。若当前接入无法实际读/写/删除，报告并保留本地可恢复点，不宣称 Drive 已验证。

## 交付与结论边界

交付中文 `research/g_v2/REPORT.md`、冻结配置/开局池、完整棋谱与评估、阶段 JSON/CSV、曲线图、最佳 G checkpoint、精确恢复状态、运行命令和自动测试。报告明确实际完成的预算节点、CPU 时间、开局数与样本置信边界。增长必须由同等 PUCT-64 对 F2 的独立开局对战支持；损失变小、单局获胜或裸网络变搜索策略不算训练增长证据。若无增长，保留 F2 冠军并如实分析。
