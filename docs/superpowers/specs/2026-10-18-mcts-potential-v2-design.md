# MCTS 极限潜力验证 V2 设计

## 目标与边界

本研究从 `research/four-ai-gomoku` 的 V1 提交开始，在独立分支增加 MCTS 极限潜力实验。V1 的 A/B/C/D 实现、报告、配置和原始棋谱必须原样保留。A、B、C 的决策逻辑不改；现有 D 保留为基线。研究对象是搜索算法与计算预算，不包含神经网络、强化学习训练或 checkpoint。

## 模型定义

- **D**：V1 原版 UCT，保持代码与 50ms 实验结果作为历史基线。
- **D1**：复制 D 的 UCT 选择、随机扩展、回传、候选策略及 rollout 走法策略；只按配置提高墙钟预算和模拟上限，并将 rollout 上限扩至当前局面的剩余空格数。它量化原算法增加算力与取消 24 手截断的合并收益，报告会单独标出两项差异，不能把 D1 的收益都归因于算力。
- **D2**：独立纯 MCTS 实现。保留 UCT，不调用 B/C 搜索。增加立即胜/必防战术检查、根节点候选公平覆盖及渐进扩展、较低开销的候选更新、战术感知 rollout、完整终局 rollout 与跨步节点复用（仅在实验 runner 的持久 agent 生命周期中启用）。每项功能可配置关闭，用固定局面消融归因。

所有模型只读取棋盘公开状态，并通过统一 `choose_move`/研究 agent 接口返回合法落点和搜索计数。每次搜索均使用从实验种子、对局 ID、ply 和模型名稳定派生的 RNG 种子。预算耗尽时返回已完成搜索中的最佳合法着法；部分 rollout 不回传且不计为完成模拟。非法着法立即判负；仅超时但返回合法着法不判负，并记录超时与实际耗时。

## 搜索观测指标

逐步记录耗时、节点/状态访问数、已完成模拟数、最大树深、平均 rollout 手数、完整终局模拟数、截断/超时中止模拟数、根候选数及最低根访问数。树深、rollout 深度与棋局 ply 分开定义。预算试验另外按 100、1,000、10,000、100,000 实际完成模拟量测固定模拟数耗时；不得仅记录配置上限。若 100,000 在试跑中不可行，报告实测吞吐和未执行原因。

## 实验赛道

1. **性能与战术基准**：9x9 为主、15x15 补充；在代表性空盘、中盘、防守、必胜/必防局面测 D/D1/D2 的模拟吞吐、耗时、深度、战术响应。预算从 50ms、200ms、1s、5s 逐级提升；根据基准决定是否纳入 10s。D1/D2 使用同一批位置和确定性种子。
2. **消融**：固定局面和种子，对比 D1 与 D2，并依次关闭 D2 的战术根检查、公平根扩展、战术 rollout、节点复用；同一时间预算及同一模拟数各跑一次，记录选择、胜率代理/战术正确率、模拟数、耗时与树深。
3. **公平赛道**：D1、D2 分别对 A/B/C，在双方相同单步时间上限下运行，预算级别依次 50ms、200ms、1s、5s，10s 只在试跑支持时追加。先小批试跑，再依据实际耗时扩到每个条件 100–200 局；优先保证 D2-C 与其他 1s/5s 关键条件有可解释的配对样本。
4. **极限挑战**：D2 用 200ms、1s、5s（试跑允许时 10s）挑战固定 50ms 的 V1 C。该结果单列为非对等算力，不能与公平排名合并。
5. **15x15 验证**：只跑可支撑统计解释的补充样本和性能曲线，并公开较宽置信区间。

每个条件用唯一 game ID、配对开局、严格交换黑白、固定种子及扩展的 4 手中央开局族；开局列表在正式运行前一次性生成并写入配置，禁止按结果筛选。对局逐局追加并 fsync 到 JSONL，启动时校验唯一 ID，只补齐未完成 ID。进度文件原子写入。

## 统计、资源与停止规则

报告每组胜/负/平、纯胜率、平局半分得分率、Wilson 95% 区间、配对开局差异、执黑/执白成绩、实际步数与耗时、模拟数、超时率及每 CPU 秒得分。排名并列或区间重叠时标为统计上未分出，不宣称小差距是算法优势。

正式评测前保存 CPU/内存/磁盘状态、D1/D2 代表局面微基准和小批完整对局的真实耗时，按实测中位数与上界估算全部任务墙钟、CPU、存储；然后按预算由低到高逐阶段扩样。若全量目标会超出可用连续运行预算，先优化实现，再优先完成 D2-C、D1-C 的配对关键条件，削减顺序须预先记录并明确标注，不能伪称达标。按每局约 1KB–10KB 估计存储，并以实测 JSONL 大小修正。

所有对局持续落盘。开始前用 Google Drive 实际上传、读取、哈希校验并恢复一个小快照。快照只含配置、代码提交标识、进度和必要 JSONL；新快照通过校验前不删除旧版，通过后才删除本任务上一版正式快照。若连接器无权访问 Drive，报告实际错误并将数据保存在 Git/本地，不声称 Drive 备份完成。运行跨 24 小时时，每 24 小时重复此更新流程。

## 交付物

新增 D1/D2 与战术测试、可复现预注册配置、性能/消融/对局运行器、统计脚本、图表、逐局原始数据、Drive 演练记录及中文 V2 报告。提交到 `research/mcts-potential-v2`，从 V1 基线创建，不改写 V1 或 `main`。测试覆盖立即胜、唯一防守点、完整 rollout/截断计数、根节点探索、稳定种子、合法着法、逐局去重、恢复校验与公平配对开局。
