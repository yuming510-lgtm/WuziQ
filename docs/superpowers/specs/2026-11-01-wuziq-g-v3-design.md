# WuziQ G V3 设计：随机初始化与 F2 初始化的自我对弈对照

## 意图

本研究回答两件事：9×9 五子棋中，32 通道、2 个残差块的策略价值网络能否通过纯 PUCT 自我对弈改善；F2 模仿预训练是否比随机初始化更快到达相同棋力。G V2 显示 F2 起点在 10k 状态训练后明显退化，G V1/V2 还观察到黑胜偏差和大量短局，因此本轮先诊断 BatchNorm 与自我对弈数据，再按预注册、有限预算比较 G0 和 G-F2。

## 目标与非目标

- 两条训练路线只在初始化不同：G0 使用固定种子随机初始化；G-F2 使用 SHA-256 校验的冻结 F2 权重。
- 统一网络、PUCT-64、优化器、学习率/调度、训练更新频率、回放规则、开局计划、评估协议和 CPU 预算。
- 训练目标只取自当前网络双方自我对弈的 PUCT 根访问分布与整局终局胜负。不开 C/E5 教师、F 监督样本、战术人工奖励或推理规则补丁。
- 两条路线至少完成每种子 10k 预算状态。预检通过后确定可执行总上限，先完成两条路线的所有登记种子各 10k，再按预注册配对批次扩展至 30k，只有预算和进度允许时再到 50k。
- 评估网络本身、固定 PUCT-64、两条路线直接对弈、F2/A/B 对手，并对最终冻结 checkpoint 进行至少 20 个新开局组、每组换色的盲测。
- 不启动 G V4、不做 15×15，不把 MCTS 搜索增益、训练损失降低或单局结果当作网络成长。

## 现有实现与影响范围

V2 已提供 `PolicyValueNet`、PUCT、完整自我对弈棋谱、逐局 fsync、经验回放、终局视角标签、严格换色评估、恢复 checkpoint 和 Drive 快照工具。当前 `GTrainer.train_updates()` 每批将整网设为 `train()`，因此 BatchNorm 运行统计量随训练样本改变；V2 只比较了学习率，没有隔离统计量更新的影响。V2 经验池按游戏均匀抽样，但自我对弈固定从黑方开局且阶段日志表现出黑胜与短局集中。

V3 复用这些成熟模块，新增版本锁定的配置、BN 机制诊断、混合开局生成器、双路线/多种子训练控制、成长评估、恢复和报告。V1/V2 目录、文件、历史分支及 checkpoint 均只读。

## 批归一化诊断

在正式训练注册前做低成本对照。对 G0 与 G-F2 分别以相同种子、相同自生成小型诊断 replay、相同更新数比较：

1. **动态统计**：V2 方式，BatchNorm 训练统计随 batch 更新。
2. **冻结初始统计**：BatchNorm 层保持 `eval` 的 running mean/variance，但其 affine 参数仍参与梯度更新。G-F2 使用 F2 初始统计，G0 使用固定种子初始统计。
3. **恢复初始统计的评测控制**：按动态统计训练，在 checkpoint 评估前临时恢复该模型初始化时的 running mean/variance 和 `num_batches_tracked`，用于区分训练期统计漂移与权重更新；不把此控制误称为独立训练算法。

诊断使用每条路线各自生成的 256 个预算状态/16 次更新，三种模式在同一初始化下回放同一份诊断经验；每种模式对该路线初始模型做 8 个开发开局组、双方换色的 PUCT-64 对照。至少记录各 BN 层运行均值/方差相对初始值的漂移、固定 probe 局面的 logits/value 变化、开发得分、策略熵与终局价值误差。模式选择规则在运行 probe 前冻结：只在动态统计与冻结初始统计间比较两路线合计的开发 PUCT-64 得分；两者差异不足 0.125 得分率时选冻结统计；差异达到 0.125 时选合计得分较高者。恢复初始统计的评测是归因控制，不参与胜负选型，也不据此声称识别训练期 batch-statistics 的总因果效应。此共同统计策略应用于 G0/G-F2 的全部正式种子。若两者都低于 0.5，仍按上述规则冻结选择，但报告 BN 策略没有恢复棋力的证据。

## 训练设计

- 目标登记至少两个配对 seed。若实测总预算无法支持两组都完成每路线 10k 状态，则降为每路线一个 seed 并在结论中明确单 seed 局限；不因此缩短 G0 训练。每个 seed 的 G0 权重由独立且可复现的随机初始化 seed 产生；对应 G-F2 使用同一个校验过的 F2 初始权重。配对 seed 共用训练开局 seed 表，但每路线/种子的模型、优化器、学习率计划、经验池、采样 RNG 和训练随机数流相互独立。开局表在不同训练 seed 间不重叠。
- 自我对弈始终由同一当前模型控制双方，PUCT 每步恰为 64 次模拟，训练期根节点 Dirichlet 噪声和温度按 V2 固定规则执行；所有对局必须走至真实终局才生成胜负价值目标。
- 冻结训练配置后，每路线每种子依次达到 1k、2k、5k、10k，若预算预注册允许再达到 30k/50k。弱的 G0 不允许在 10k 前因成绩被淘汰。
- 训练状态数按预算前缀计，完成整局的尾步单独记账且不进入经验池/训练步数。每个 milestone 原子保存模型、优化器、scheduler、replay、Python/NumPy/Torch RNG、配额和棋谱索引。
- 训练开局固定为 50% 空盘、50% 合法随机四手局面；空盘是所有模型共同的任务起点，不声称它是 held-out。随机四手训练组在 seed 间不重叠，G0/G-F2 在匹配 seed 间共用同组。开发与盲测局面仅用随机四手开局，开局池跨所有路线/seed 共用，并与训练随机开局、彼此以及 G V1/V2 所有非空登记开局做 D4 对称去重。训练过程记录黑白胜、和棋、完整局长、短局率、访问熵和经验覆盖。
- 经验池仅接受本臂本种子的纯自我对弈经验，按游戏均匀抽取，保留有界容量；训练失败/退化候选不会覆盖 lineage incumbent。

## 评估和模型选择

- 随机四手开发开局 D4 对称隔离于训练和最终盲测；每个 milestone 对比裸网络与同一 PUCT-64，分别挑战路线自身冻结初始 checkpoint、冻结 F2 历史冠军、A 和 B，并在配对种子上直接进行 G0 vs G-F2。每个主要对手在每阶段至少用 4 个开局组换色；晋级用 12 组，最终盲测用 20 组。所有比赛换色，种子和先后手预先登记。由于空盘是唯一普遍任务起点，本轮不把空盘 self-play root 声称为未见测试开局。
- 每个 milestone 的裸网络和 PUCT-64 都参加独立精确战术题评估。题目由本地五连规则生成并回放验证，覆盖直接取胜、唯一必防、边缘局面和伪威胁；只评分选点，不把题目作为训练样本/奖励，也不添加推理期硬编码规则。终局价值用 held-out 开发棋谱结果报告 MAE/MSE 和分桶校准。
- incumbent 晋级规则在 probe 及正式训练前登记：对该 seed 的路线 incumbent 用 PUCT-64 进行 12 组换色开局；挑战者得分率至少 0.625，按开局组 bootstrap 的 95% 下界高于 0.5，且黑白分项均不低于 0.5，才可晋级。否则 incumbent 不变，所有 challenger 仍按预算训练到共同终点。G0 的 lineage incumbent 从其随机初始模型开始；G-F2 的 lineage incumbent 从冻结 F2 开始。F2 历史 champion 对两路都是固定外部对手/比较线，不因 G0 的晋级而替换。
- 每个 seed 的 G0 与 G-F2 最终 checkpoint 都独立进入盲测，不只选表现最佳的 seed。每个 seed-checkpoint 对 F2、A、B、另一路线匹配 seed checkpoint，裸网络和 PUCT-64 分别比较；每个 matchup 至少使用同一批 20 个全新开局组并各换色（40 局）。报告每 seed 结果和范围；配对开局 95% bootstrap 只表达该 seed 下的开局不确定性，不冒充训练 seed 的统计不确定性。只有两个 seeds 时，路线间总体优劣和成长差异均标为探索性。
- “棋力成长速度”的主要量是在相同累计 CPU 秒处 G0 与 G-F2 的冻结开局 PUCT-64 得分率差；另画相同预算状态节点处的得分率差，清楚标明这是状态数对照而不是等墙钟。达到相同棋力的效率只在某路线 checkpoint 对冻结 F2 的 PUCT-64 得分达到 0.5 且其配对区间下界大于 0.5 时记录该路线达到/超过基准的状态、完整局数和 CPU 秒；未达门槛就标记“预算内未达到”，不从曲线外推。
- 每条路线每 seed 的正式晋级比较只由开发集决定；选择规则固定按最终登记节点挑战 lineage incumbent 的得分、配对下界、预设 seed 顺序排序。晋级失败时路线初始冠军保持原权重。历史 F2、A、B 和另一路线都作为固定报告比较项，不按盲测修改 checkpoint。
- 盲测至少 20 个全新开局组/seed-checkpoint-m matchup，每组交换黑白。冻结最终候选后一次性评测；开发结果不能读盲测结果后再调参。
- 分开报告：训练收益（同搜索模式下初始 vs 训练模型）、搜索收益（同 checkpoint 裸网络 vs PUCT-64）、初始化差异（匹配 seed、相同状态数的 G0 vs G-F2）、计算效率（相同累计 CPU 秒的差异）。

## 预算、停止条件与资源

云端预检实测 BN 诊断、PUCT64 自我对弈、训练更新、评估局速度和峰值内存。先目标登记两条路线各两个配对 seeds、每个 seed 至少 10k 状态、预期 30k 目标和最高 50k 目标；只有中性估算不能在登记 CPU 上限内完成这一底线时，才降为两路各一个 seed并明确标为单 seed 探索性结果。随后按真实乐观/中性/保守测量注册 CPU 上限。主要比较量、开局组级统计方式、晋级阈值、BN 选择规则、seed 单位、盲测 matchup 及每个候选的开局配额均须在正式盲测前写入配置 SHA。先完成两路所有 seed 的 10k 底线，再以配对 seed 和相同状态数一起扩展。达到登记预算、磁盘/恢复校验失败或评估/训练出现不可恢复错误时停止扩展并如实报告；不无限续训。最终盲测和必要验证也须计入预注册总成本。

## 恢复、产物与验收

新分支 `research/alphazero-g-v3` 以 `c95eb5aa919c769af11ea6b7fc22df2594ae1c28` 为基线。G0/G-F2 新 checkpoint、配置、开局表、棋谱、阶段统计、图表、恢复 manifest、CPU 预算和中文 `REPORT.md` 均保存在 `research/g_v3/`，复用 V2 Drive 快照机制但使用独立 V3 目录。快照仅包含恢复所需代码/配置/权重/replay/棋谱/进度；新包上传、回读哈希与空目录恢复通过后才删除旧 V3 包。

验收包括：统一配置哈希和 F2 起始权重哈希、每 seed 配额和 PUCT 模拟数核算、V2/Python 价值视角和 BN 行为单元测试、棋谱完整合法回放、训练恢复与不中断等价、开局/种子去重与 train/dev/blind 隔离、报告/CSV/图表与原始记录一致、CPU 时间不超过登记上限、GitHub 远端分支与最终提交可核验。

## 实施途径

1. **重写 AlphaZero 训练栈**：可大改数据/BatchNorm 机制，但会改变更多变量、提高回归和恢复风险，且不符合复用 V2 的要求。
2. **直接运行 V2 两次**：改动少，但没有 V3 的 BN 诊断、混合开局、双种子配对和统一对照/报告，不能回答核心问题。
3. **推荐：保留 V2 内核，新增 V3 控制层**：在 V2 训练器/PUCT/回放上加入 BN 模式探针、统一冻结配置、多随机种子配对、混合开局和 V3 专属统计/恢复/报告；仅在预检证明必要时对训练器增加最小 BN 策略钩子。选择它可使算法变化最少且直接复用已验证的恢复能力。

## 留给实施者的决定

只有真实吞吐量、BN probe、CPU 预算估算和最小测试结束后，才冻结实际登记的 state 节点（最低每 seed 每路线 10k）、最终盲测可用时间预算和 Drive 快照阈值；本设计已预注册上文的两 seed 目标、统计对象、BN 选型优先序、晋级分数阈值与盲测开局组配额。所有最终登记项写入配置 SHA-256 后，不得按模型成绩临场更改。
